# HomeControl

A macOS menu bar app for Philips Hue and TP-Link Kasa devices, plus a small Python backend that talks to them.

```
make install    # builds, copies to /Applications/HomeControl.app (~/Applications if that isn't writable), launches it
make run        # builds and launches build/HomeControl.app without installing
```

Turn on Settings → Customize → Launch at login to start it with your Mac.
The app still runs its backend and updates from this folder (the source checkout), so leave `homecontrol-app/` where it is. If you move it, run `make install` again from the new location.

## Where things live

| Path | What |
|---|---|
| `~/Library/Application Support/HomeControl/config.json` | All app settings and presets. Written by the app; hand edits are picked up automatically. |
| `~/Library/Application Support/HomeControl/.env` | Secrets: `KASA_USERNAME`, `KASA_PASSWORD`, `HUE_USERNAME` (bridge key), optional `HOMECONTROL_TOKEN` |
| `~/Library/Logs/HomeControl/` | `backend.log`, `update.log` |
| this folder | Source, backend, its Python venv. Nothing personal, so it's safe to re-clone. |

On first launch after upgrading from 0.1.1 or older, `config.json` and `.env` are copied from this folder to Application Support. The old copies are left behind and can be deleted. Set `HOMECONTROL_DATA` to use a different data folder.

## Versions and updates

The version lives in `VERSION` (release.major.minor). The app checks `main` on GitHub at launch and every few hours; when a newer version exists, an **Update** button appears in the menu bar popover and in Settings → Advanced. Clicking it runs `scripts/update.sh`, which pulls, rebuilds and relaunches the app (log: `~/Library/Logs/HomeControl/update.log`). If a copy is installed in /Applications it is replaced. Self-update needs this folder to be a git checkout. Bump the version with `scripts/bump-version.sh`.

## Layout

| Path | What |
|---|---|
| `backend/` | `server.py` (aiohttp API), `hue.py`, `kasa_provider.py` |
| `macos/` | SwiftUI app (Swift package); `macos/Resources/AppIcon.icns` is generated by `scripts/make-icon.swift` |

## Backend

With *Settings → Advanced → Host* blank, the app starts `backend/server.py` on `127.0.0.1:8790`. It restarts the backend if it crashes, and the backend exits when the app quits.

To use another machine as the backend, copy this folder there, put a `config.json` and `.env` next to `backend/` (or pass `--config` / `--env`), and run:

```
./scripts/setup-backend.sh
backend/.venv/bin/python backend/server.py --host 0.0.0.0 --port 8790
```

Then put that machine's hostname in Settings → Advanced. If you set `HOMECONTROL_TOKEN` in that machine's `.env`, enter the same token in the app.

API (all JSON):

```
GET  /health
GET  /devices                    -> {devices: [...], errors: {hue?, kasa?}}
POST /devices/{id}               {on?, toggle?, brightness? 0-100, color? "#rrggbb", color_temp? K, name?}
POST /run                        {mode: parallel|sequential, delay_ms, steps: [{device_id, action: on|off|toggle, brightness?, color?, color_temp?}]}
GET  /integrations/hue/test      POST /integrations/hue/pair {bridge_ip}
GET  /integrations/kasa/test     POST /reload
```

## Device IDs

Presets refer to devices by an ID that doesn't change when you rename a device:

- **Hue:** `hue:<uniqueid>`, where uniqueid is the bulb's Zigbee MAC (e.g. `hue:00:17:88:01:0d:bf:61:0e-0b`). It stays the same when the bridge renumbers lights.
- **Kasa:** `kasa:<deviceId>`, a hardware ID reported by the plug (each power-strip outlet has its own). It stays the same when the device's IP changes.

The only case where an ID changes is replacing the physical device.

## Building without Xcode

On a Mac with only the Command Line Tools, the macOS 27 SDK's SwiftUI needs a macro plugin that ships only with Xcode. `build-app.sh` notices this and builds against the newest installed macOS 26 SDK. With Xcode installed, it uses the default SDK.
